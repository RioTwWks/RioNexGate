# Stealth / Anti-DPI Configuration

RioNexGate generates Xray-core and sing-box configs designed to resist modern DPI (2026) using **official Xray-core** — no forks.

## Transport profiles

| Priority | Stack | Port (default) | Use case |
|----------|-------|----------------|----------|
| Primary | VLESS + Reality + XHTTP (`mode: stream-one`) | 443 | Best traffic masking; recommended default |
| Fallback | VLESS + Reality + Vision (TCP) | 8443 | iOS and clients without XHTTP |
| Mobile | VLESS + TLS (optional) | configurable | Last resort; enable `mux` on client (concurrency 8) |

Each active user receives **one link per enabled inbound** for subscription fallback.

## Why official Xray-core only

- Forks like `fwflunky/REALITY-rkn-fix` lack tests and lag upstream.
- Security fixes and XHTTP/Reality improvements land in [XTLS/Xray-core](https://github.com/XTLS/Xray-core) first.
- proxy-mgr pins a tested `XRAY_VERSION` in Docker and validates configs with `xray run -test` in CI.

## Configuration (`core.stealth`)

See [`backend/config.example.yaml`](../backend/config.example.yaml) for a full example.

```yaml
core:
  public_host: "your.domain"
  stealth:
    enabled: true
    fingerprint: firefox    # or edge — avoid chrome/safari defaults
    reality:
      dest: "cdn.example.com:443"
      server_names: ["cdn.example.com"]
      private_key: "..."
      public_key: "..."
      short_ids: ["a1b2c3d4"]
    xhttp:
      enabled: true
      port: 443
      path: "/api/v1/data"
      mode: stream-one      # required — do not use auto
    vision:
      enabled: true
      port: 8443
```

### Reality keypair

```bash
# Inside xray container or with xray binary installed:
xray x25519
# PrivateKey: ...  → core.stealth.reality.private_key
# Password: ...    → core.stealth.reality.public_key (pbk in client links)
```

### Choosing `dest` (impersonation target)

1. Pick a **little-known legitimate HTTPS site** in a CDN zone you control or trust (e.g. `.okcdn.ru`), not popular targets (`yahoo.com`, `vk.com`) — they attract extra scrutiny.
2. Verify reachability from the server:

```bash
curl -vI --connect-timeout 5 "https://cdn.example.com"
```

3. Set `dest` to `host:443` and `server_names` to the TLS SNI hostname.

### Fingerprint

Default `firefox` or `edge`. Configurable via `core.stealth.fingerprint`. Passed to clients as `fp=` in VLESS URLs.

### ServerHello fragmentation (`core.stealth.fragmentation`)

Xray **v26.3.27** supports `finalmask.fragment` with `packets: tlshello` (first TLS record) or `1-3` (aggressive). Defaults: disabled, `length: 50-100`, `delay: 10-20`, `max_split: 2-4`.

**Partial:** REALITY inbounds cannot use finalmask yet — crashes Xray ([#6453](https://github.com/XTLS/Xray-core/issues/6453)). Fragmentation is emitted only on VLESS+TLS inbound. Panel: `GET`/`PUT` `/api/stealth/settings`.

## Deployment

1. Enable `core.stealth` in `backend/config.yaml`.
2. Open host ports **443** and **8443** (xray-core profile uses `network_mode: host`).
3. Run `make dev-cores` after panel users exist.
4. Fetch multi-profile links: `GET /api/users/{id}/link?all=true`.

Docker pins Xray via `XRAY_VERSION` (default `26.3.27`) in `docker-compose.yml` / `Dockerfile.xray`.

## Client links

Generated by `core/links.go`:

- **XHTTP**: `type=xhttp`, `security=reality`, `pbk`, `sid`, `fp`, `path`, `mode=stream-one`
- **Vision**: `flow=xtls-rprx-vision`, `security=reality`, `type=tcp`
- **TLS**: `security=tls`, `sni`, `alpn`

Subscription format (when `/api/subscription/{token}` is implemented): base64 of newline-separated links.

## Production checklist

- [ ] Reality keypair generated; `public_key` matches `private_key`
- [ ] `dest` reachable from server (`curl -vI`)
- [ ] XHTTP `mode` is `stream-one`
- [ ] Ports 443 and 8443 listening (`ss -tlnp | grep -E '443|8443'`)
- [ ] `xray run -test -c data/xray/config.json` passes
- [ ] Test each inbound from a real client on staging
- [ ] Pin `XRAY_VERSION`; read Xray release notes before upgrade

## Not in scope (yet)

- ServerHello fragmentation on REALITY inbounds (upstream crash)
- Multi-hop node chains (`Node` entry/exit)
- AmneziaWG sidecar

## Threat model (server side)

| Threat | Mitigation |
|--------|------------|
| VLESS+Reality TCP fingerprinting | Primary path uses XHTTP (`stream-one`) |
| Long TCP without HTTP after TLS | XHTTP mimics HTTP upload/download |
| Static Reality cert structure | Choose diverse `dest`; watch upstream impersonation options |
| Single transport block | Multiple inbounds + multi-link subscription |

## Upgrading Xray-core

1. Check [Xray releases](https://github.com/XTLS/Xray-core/releases) for XHTTP/Reality breaking changes.
2. Bump `XRAY_VERSION` in `.env` or `docker-compose.yml`.
3. Rebuild: `docker compose --profile cores build xray-core`.
4. Run `xray run -test -c ./data/xray/config.json`.
5. Smoke-test all three profiles from a client.

## AmneziaWG (UDP reserve)

Optional fallback when the Xray stack is blocked. See `core.stealth.awg` in config.example.yaml.

| Scenario | Use |
|----------|-----|
| Default anti-DPI | XHTTP + Reality |
| Xray blocked | AmneziaWG UDP reserve |

Subscription adds `awg://` URI line; profiles API returns raw INI in `config` field.

```bash
docker compose --profile awg up -d amneziawg
```
